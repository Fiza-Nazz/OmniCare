## 1. Summary
Establishes the automated code hygiene, linting, formatting, security scanning, and CI pipeline for OmniCare. Configures `ruff.toml` with strict rules (E, F, W, I, N, UP, B, S, A, C4, T20, SIM, PTH), defines `.editorconfig` for uniform formatting across IDEs, adds `.github/workflows/ci.yml` for automated CI validation, and introduces `scripts/verify_codebase.py` to continuously verify zero committed secrets/PHI and check Python AST syntax.

## 2. Problem
Without strict automated linting and pre-commit verification, inconsistencies in code style, unsafe constructs (such as debug `print` statements in production services or weak crypto defaults), and accidental credential leaks can slip into the codebase, violating Constitution §4, §24, §25, and §65.

## 3. Implementation Details
- Configured `ruff.toml` targeting Python 3.11 with line length 88, import sorting (`isort`), security auditing (`flake8-bandit`), and disallowed raw print statements (`T201`).
- Added `.editorconfig` setting LF line endings and UTF-8 charset across all file extensions.
- Created `.github/workflows/ci.yml` orchestrating:
  - Ruff lint & format check
  - Security and secret verification via `scripts/verify_codebase.py`
  - Automated Pytest execution against PostgreSQL 16 & Redis 7 test containers
  - Next.js frontend lint and build checks
- Implemented `scripts/verify_codebase.py` validating AST syntax and regex patterns for private keys and leaked tokens.

## 4. Security Considerations
- Included `flake8-bandit` (`S` rules) in `ruff.toml` to catch insecure standard library functions, weak hashing, and improper shell execution.
- Tested `scripts/verify_codebase.py` locally against all project files; verified zero hardcoded secrets.
